### 引用校验与证据兼容

- `agent/src/ssv_agent/result.py` 的 `validate_rule_citations` 仅使用本次预检索候选，核对 `chunk_id`、`source`、`rule_id`、`rule_version`、`section`。确定性结论没有可用规则、没有引用或引用不符时降为 `uncertain`；失败检索返回的部分 chunks 不能授权确定性结论。
- `validate_rule_citations` 保留可选的 `ReviewContext` 参数；显式传入且事件声明 `event_type` 时，确定性引用的规则必须在 `event_types` 中声明该类型。采用远端 worker 后，生产调用不传入此参数，不执行该项事件类型约束。
- `uncertain` 结果也清理不存在或身份不符的引用，在说明中注明移除数量，保留可核对引用；不因此把不确定结果变成确定性结论。
- `agent/src/ssv_agent/workers.py` 的 `ReviewWorker.run_once` 按远端版本仅在配置检索器时构造 `rule_context` 并执行规则引用校验；未配置时以 `None` 调用 runner 并跳过该项程序校验。
- `parse_review_result` 保留可选的 `available_evidence_ids`。显式传入本事件当前可用证据集合时，按顶层 `evidence_ids`、各 `claims.evidence_ids` 的顺序汇总已出现的引用并去重；任何未登记、不可用或其他事件的 ID 都拒绝。它只修复汇总漏列，不生成观察、事实或新结论。当前远端 worker 调用不传入此参数。
- worker 与其他未传可用集合的解析调用使用严格汇总契约：模型须在顶层显式声明 claims 引用的全部证据，漏列则拒绝结果并由任务重试处理；历史 Markdown 同样检查证据归属。`ReviewResult` 保留基线字段，历史 JSON 中额外的 `checks` 允许读取，但不解释、不要求输出，也不再参与证据汇总。
- `agent/src/ssv_agent/prompt.py` 的 `build_review_prompt` 说明基础引用范围、事件类型和视觉证据边界。模型依据规则正文、登记 `rule_facts` 和已查看的证据判断，不能补造前提。程序校验身份与证据归属，不保证每句视觉描述都准确。

当前不追踪工具调用新增的可引用集合；模型通过工具单独检索到、但不在预检索候选中的片段仍不能支持确定性引用。这是撤去全目录候选兜底后保留的限制。
